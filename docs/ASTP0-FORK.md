# MiTV-ASTP0 定制版

基于上游 v0.3.0，为 MiTV-ASTP0 / Android 9 增加实验性完整开机和待机唤醒入口。

## 与官方版并存

- applicationId：`io.github.minggnim.guizangtv`，显示名称“哈怪鱼电视”。
- 官方版 `io.github.op7418.guizangtv` 不覆盖、不卸载，其数据保持原状。
- CI 产物仍为临时 debug 签名。电视部署包在本机用 `.local-signing/` 中的固定身份重新签名；私钥和密码仅存本机且被 Git 忽略，不上传 GitHub。后续部署必须沿用该签名。
- 不新增网络权限、遥测或悬浮窗。可选的屏保返回使用经明确授权的无障碍窗口事件监听，不读取界面内容、不拦截按键。启动恢复使用通知监听绑定（不处理通知内容）；保持 ADB 使用 WRITE_SECURE_SETTINGS，均须显式授权。
- 未改 HDMI 型号白名单：支持启动不意味着 HDMI 已适配。

## 启动设置

两个独立选项均默认关闭：完整重启后进入、待机唤醒后进入。保存时应用本地偏好。

完整开机使用系统 BOOT_COMPLETED。仅在启动十分钟内、可读取启动编号、尚未尝试本次开机、屏幕亮着时启动一次。记录尝试后才启动，失败不循环抢占。

待机唤醒使用低优先级通知的前台服务，动态监听 SCREEN_OFF / SCREEN_ON。只在观察到关屏再亮屏时延迟两秒打开一次；关屏会取消待执行动作。无轮询、无唤醒锁、不处理 Home。系统重启服务时，仅有已记录关屏状态才尝试补偿一次。

**限制：** 小米若 force-stop 应用或禁止开机广播，前台服务和 START_STICKY 都不能保证恢复。该分支实现不承诺绕过厂商清理策略。关闭两项会停止服务；关闭唤醒也会取消待执行动作。后台启动规则仅针对 Android 9，其他系统禁用此功能。

## 设置迁移

官方版不可调试且禁止 Android backup，未取得其私有偏好备份。可以根据官方版的 `dumpsys activity` 诊断和用户确认生成白名单 JSON，再导入新包；这不是完整应用数据备份。私人 JSON 不提交仓库。

新包首次打开前，用 shell 发显式广播给 `io.github.op7418.guizangtv.SettingsImportReceiver`，传 `json` 字符串。该 receiver 由系统 `android.permission.DUMP` 保护，普通第三方应用不能调用。只接受 schema=1 的外观、首页排序和内置壁纸偏好，不接受任何自启权限或自启开关；已有偏好或已迁移时拒绝覆盖。

JSON 示例（仅结构示意）：

```json
{"schema":1,"appearance":{"layout":0},"items":["com.mitv.tvhome"],"wallpaper":{"selected":"从内置 catalog 读取有效 id","rotating":false,"minutes":5}}
```

## 待执行的真机验收

1. 官方版原始设置仍在；定制版导入后布局、首页顺序和壁纸逐项匹配。
2. 两个启动选项关闭时，普通打开和退出正常，默认 Home 不变。
3. 开启完整开机选项，完整重启后观察实际前台；单纯发出请求不算成功。
4. 开启唤醒选项，实体遥控器关屏、等待、唤醒，分别从桌面和视频场景检查。
5. 观察是否被强停，是否会在正常观看中抢占画面；测进程 PSS 和 CPU。
6. 关闭选项后，再次唤醒和重启，确认不再自动进入。

截至实现时仅为待验证方案；构建与单元测试不能替代这些验收。

## ASTP0 待机清理修复

设备日志证实：待机/软重启会 force-stop 归藏并停止前台服务，START_STICKY 不足以恢复。新增 StartupRevivalListener 利用系统通知监听绑定恢复进程；它不读取、存储或处理通知内容。后台恢复只在观察到关屏/亮屏转换时打开一次，不在正常观看中循环抢占。

保持 ADB 是独立选项，默认关闭；用户请求启用时授予 WRITE_SECURE_SETTINGS 并打开 keep_adb。事件监听 global adb_enabled，若固件关闭调试会恢复为 1。要手动关闭 ADB，先关闭应用的保持 ADB 选项。通知监听和设置权限可分别撤销，不需要 root 或停用系统应用。

设置保存会显示确认，并把开机广播、屏幕事件、监听绑定及启动结果保存在诊断字段中。完整重启与待机必须分别验收；启动编号不变不能算完整重启。
